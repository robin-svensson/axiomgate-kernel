## Reporting bugs and security issues

Open an issue. Include the command you ran and the full output; the repo's own
claims are mechanically verified (`scripts/verify_claims.sh`), so reproduction
steps help more than a description alone.

For security vulnerabilities, please open a **private** security advisory via
GitHub rather than a public issue.

## Asking questions

Open an issue for technical questions. For commercial use, integration, or
licensing enquiries, email robinsvensson493@gmail.com — GitHub has no private
messaging, and a commercial enquiry does not belong in a public thread.

## Code contributions

Because of this license, pull requests that add features or change behaviour
cannot be accepted unless they come from the maintainer. Bug reports and
documentation improvements via issues are always welcome.
